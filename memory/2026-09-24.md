Tim 说"忘记登录密码了，打不开"。查下来根本不是密码问题，是服务压根没跑。

**9/22 那次升级的后半段（我第一次没看到的）**
- `/tmp/node-upgrade.sh`（agent 写的、launchd 脱离会话执行）：
  换 Node → v24.21.0、npm/corepack 一起换、跑 `openclaw update --yes`

**真正的病根（doctor 点破的）**
> Gateway LaunchAgent is installed but **unloaded and disabled in launchd**.
> A terminated update helper can leave it disabled across logins.

被掐断的升级助手把服务在 launchd 里**禁用**了 → plist 在、`launchctl load` 还返回成功，
但服务永远不会起来。这也是 9/22 那天"`gateway install` 之后又没了"的答案。

**修复路径（按它自己给的顺序）**
1. `openclaw update repair` → 推进被推迟的插件状态迁移（kimi/moonshot/feishu）
2. 撞到一个拒绝继续的迁移：
   `credentials/feishu-alita-allowFrom.json` → "Legacy channel allowFrom channel/account is unresolved"
   - 溯源：6 月配置有 `alita`/`wukong`/`default` 三个飞书账号，该文件指向已废弃的 `alita`，
     里面的 `ou_0115242d…` 属于更早那个 app（现在只剩 `alita2` / `cli_aaaeb986…` / `ou_07c2cadc…`）
   - 读源码确认合并语义是 `[...existing, ...entries]`（追加，不是覆盖）→ 无锁死风险
   - 处理：改名成 `feishu-alita-allowFrom.retired-20260924.json`（+ `.bak` 双份），不删内容
3. `openclaw doctor --fix` → **complete，exit 0**
4. `openclaw gateway start` → 自己 bootstrap（`install` 当时被 auth-profile 迁移错误挡住了）
5. 验证：PID 49075，18789 在听，UI 200，飞书 ws ready，`openclaw agent` 实测回话
6. 确认 Tim 的 open_id `ou_07c2cadc…` 仍在 `state/openclaw.sqlite` 的 allowFrom 里 → 没被迁移弄丢

**"登录不上"的真相 = 浏览器缓存了旧版 Control UI**
```
[ws] control ui build rejected clientBuild=legacy gatewayBuild=2026.9.5…; reload required
phase=auth_validated cause=control-ui-build-mismatch
```
`phase=auth_validated` → 鉴权是过的，是**前端构建版本不匹配**。硬刷新（Cmd+Shift+R）即可。
另：OpenClaw 的登录凭据是 **token** 不是密码（`gateway.auth.mode=token`，48 位），
`openclaw dashboard` 会带着它开浏览器。别再找"密码"了。

**期间插曲：有另一个 agent 进程在同时修**
21:17 出现 `/tmp/openclaw-fix.sh`（同一个套路：写脚本 + launchd 脱离执行），先 `launchctl unload`
