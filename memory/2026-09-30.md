## OpenClaw 抢修（20:08 ~ 20:30）

Tim 说"帮我修复 OpenClaw"。没给症状，自己摸的现场。

**症状**：网关进程活着、UI 200，但所有对话 401。日志显示 deepseek key 从 18:28 起失效
（尾号 5ef7），飞书上发给它的消息也全部失败。

**三层坑，一层套一层：**

1. **配置被判 invalid 锁死了所有修复入口。** `channels.feishu.streaming` 是个空对象 `{}`
   （升级残留），新版要求 boolean。后果不是"飞书流式不生效"，而是整个 config 判 invalid，
   `config get/set`、`models auth *`、`gateway start` 全部拒跑 —— 想修都不知道从哪下手。
   出口只有 `doctor --fix`。
2. **`doctor --fix` 把网关停了没拉回来。** 它要求先停网关（否则
   `AgentDatabaseLeaseActiveError`），停完自己重启失败。我又补了一次 `doctor --fix`
   （这次旧进程已退，成功了）才把网关救回来。过程中服务是真断的。
3. **换 key 死活不生效 —— 真凶是环境变量。**
   `~/.openclaw/service-env/ai.openclaw.gateway.env` 和 `~/.openclaw/.env` 里写死了
   `DEEPSEEK_API_KEY`，**优先级压过 `openclaw.json` 里的 apiKey**。所以我改 config、
   Tim 跑 `paste-api-key`，全都没用，它照旧拿旧 key 去请求。
   正确姿势：`export DEEPSEEK_API_KEY=新key && openclaw gateway install --force`。
   另外 `config set` 提示"will apply without restarting"是假的，apiKey 改动必须重启。

**顺带搞清 moonshot / kimi 是两个东西**：`moonshot/` 是开放平台（国内走 `api.moonshot.cn`），
`kimi/` 是 Kimi Coding（要 `api.kimi.com` + Anthropic 协议 + 另一套 key）。Tim 的配置把
kimi provider 指向 moonshot.cn，所以一直 400；moonshot 走默认国际站，所以 401。
补了 `models.providers.moonshot` 指向国内站后通了。

**结果**：主模型恢复，配了 fallback 链 `deepseek-v4-pro → moonshot/kimi-k2.6 → moonshot/kimi-k3`，
飞书通道 running。

**教训**：报"服务在跑却用不了"，先验第一跳没错；但**换凭据不生效时，要往上找优先级更高的一层**
（env > config），别在 config 里反复较劲。

完整技术细节 → `memory/topics/local-services.md`（新增三.5 / 三.6 两节）
