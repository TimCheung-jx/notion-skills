# 2026-10-04

## OpenClaw 二次掉线 —— 真因是插件/内核版本错配

Tim：`为何我的openclaw又掉线了`（16:14）。

**症状**：gateway 进程完全没有，`ai.openclaw.gateway` 在 launchd 里 exit code 78，
日志被 `OpenClaw config is invalid; run "openclaw doctor --fix" before startup.` 刷屏 —— 
launchd 反复拉起、每次都被配置校验挡回，崩溃循环。

**和 09-30 是同一个报错字段，但这次的结论完全不同：**

| | 报错 | 含义 |
|---|---|---|
| 09-30（老插件 2026.6.1） | `streaming: must be **boolean**` | 字段是 `{}`，老插件不认 |
| 10-04（更新插件后 2026.9.5） | `streaming: must be **object**` | 字段是 `false`，新插件不认 |

**同一个字段，两版插件要的类型正好相反。** 所以 09-30 那个 `{}` 根本不是"升级残留的坏值"，
它恰恰是**新版插件期望的格式**；我那次按老插件报错改成 `false`，只是让配置迁就了当时
加载的老插件，把矛盾暂时压住了。

**复发链条**：09-30 改成 `false` → 老插件满意、服务跑起来 → 10-02 22:06 插件重写配置
（塞回它自己的格式）→ 但当时 gateway 没重启，内存里的配置还是好的，Tim 22:08 还在飞书上
正常对话 → 之后机器睡眠/重启，gateway 重新加载磁盘上那份 → 校验失败 → 起不来。

**修复（关键是绕开鸡生蛋）**：
1. `doctor --fix` 先恢复（网关本来就是停的，这次没有额外中断）
2. `openclaw config unset channels.feishu.streaming` —— **把字段整个删掉**，
   让插件用自己的默认值。因为装新插件时要校验配置，而配置是按老插件格式写的，会死循环
3. `openclaw plugins update feishu` → 2026.6.1 → **2026.9.5**，与网关对齐
4. 重启验证

**结果**：飞书通道 `running, connected`（比之前只到 running 更进一步），
doctor 里的「插件版本漂移」警告消失，重启后配置没再被改写。

**教训**：**版本错配会伪装成配置错误。** 判定信号是——
当你"按报错改了值"，重启后报错要求的类型**反转**了（boolean ↔ object），
那就不是值错了，是两个组件对同一份配置的契约不一致，修值永远治不好，
得把版本对齐。只改配置 = 让两边暂时握手，下次组件重写必然复发。
