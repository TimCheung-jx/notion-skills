# Case Archive — 案件档案与定期汇报

把杂乱的法律材料变成一份持续维护的**案件档案**，再从档案生成**只报变化的定期汇报**。适用于诉讼、仲裁、合规专项等任何"材料持续涌入 + 周期性向上汇报"的场景。

## 核心设计——先读懂，再动手

三条铁律，每条都是真实取舍的产物，不要绕过：

1. **档案是唯一事实源，永远增量更新，不做全文重摘。** 同一批材料重摘两次，说法必然漂移；汇报前后不一致对法律工作者是致命的。时间线只追加不重写；需要更正时，追加一条更正条目并注明，不动旧条目。
2. **每个节点必须带引用回链。** 文书类：文件名 + 页码；邮件类：日期 + 主题（发件人）。用户会靠抽查回链来决定信任程度。没有来源支撑的信息标注「待核实」，绝不补全、绝不编造——一个编造的日期就能毁掉整份档案的信誉。
3. **邮件抽取的是状态变化，不是摘要。** 承诺、期限变更、立场调整、新设截止日、费用安排——这些才是节点。「双方保持沟通」不是节点。

预期管理：第一轮建档的判断精度有限，随档案变厚而上升。低置信度条目明确标注，这是特性而非缺陷，隐瞒才是。

## 目录约定

```
workspace/cases/<案件代号>/
├── inbox/            # 原始材料（文书 PDF/DOCX/扫描件、.eml 邮件导出），只进不改
├── reports/          # 生成的定期汇报
├── archive.md        # 案件档案（唯一事实源，本技能维护）
└── _processed.md     # 已处理材料清单（增量摄取的依据）
```

- 案件目录名用**代号**，不用真实案名——工作区里留全名没有好处。
- 初始化时把 `assets/archive-template.md` 复制为该案的 `archive.md`。

## 工作流

### A. 初始化（每个案件一次）

1. 建目录结构（含空的 `inbox/`、`reports/`），复制档案模板，创建空的 `_processed.md`
2. 与用户确认：汇报节奏（如每两周周五）、汇报形态（PPT / Word / Markdown）、汇报生成时点（建议汇报日前一晚）

### B. 增量摄取（材料进入时、每次汇报前执行）

1. 列出 `inbox/` 全部文件，与 `_processed.md` 对比，找出未处理项
2. 按类型解析：
   - **PDF/DOCX**：直接读文本；扫描件/图片用平台 OCR（MyAgents 平台用 `myagents anydoc`；无此能力时告知用户识别受限，请其提供文字版，不要硬猜）
   - **.eml 邮件**：`python3 <本技能目录>/scripts/parse_eml.py <file.eml>`——解析出头信息、正文、附件清单；重点字段：Date、From/To、Subject、In-Reply-To/References（线程关系）。附件落入 `<eml名>_attachments/`，其中的文书按上条规则继续处理
3. 每处理完一个文件，立即在 `_processed.md` 登记一行（文件名、处理日期、类型、备注）
4. 解析失败的文件如实告知用户，不静默跳过

### C. 档案更新（摄取后立即做）

按 `archive.md` 各节的既有格式增量更新：

- **案件概要**：有新事实才改；改前先看旧内容，避免口径漂移
- **时间线**：只追加新行，格式 `| 日期 | 事件 | 来源 | 状态变化 |`
- **关键节点与问题**：每个节点回答三件事——发生了什么 / 影响 / 待办
- **未决问题与风险**：注明依据与紧迫度；已解决的标记而非删除
- **下一步**：从材料中的期限、承诺、待办提炼，带截止日
- **汇报记录**：每次生成汇报后登记（见 D）

低置信度标注：在条目后加 `（待核实：原因）`。

### D. 定期汇报生成

1. 读 `archive.md` 全文 + 「汇报记录」里上一期的覆盖区间
2. 汇报**只包含上一期以来的变化**：本期进展、新增或变化的关键节点、风险变化、下一步计划。上一期已经汇报过的内容不再复述——用户不需要把同样的东西看两遍
3. 形态与渲染：PPT 优先用平台已有的 `pptx` 技能；有企业风格技能（如 `liby-corporate-ppt-style`）则套用其版式；Word/Markdown 同样只报 delta
4. 存为 `reports/YYYY-MM-DD_案件汇报.pptx`（用案件代号命名）
5. 在 `archive.md` 的「汇报记录」登记：日期、覆盖区间、文件名

### E. 定时自动化（可选）

**前置条件：首轮建档完成后，让用户抽查 2–3 条引用回链，验收通过再挂定时任务。** 空档案或未验收的档案跑定时任务，只会按时产出垃圾。

- MyAgents 平台：按 `references/myagents-task-setup.md` 创建每 14 天的定时任务
- 其他平台：告诉用户在汇报节奏点手动说一句「生成 XX 案件本期汇报」即可触发 B→C→D

## 安全与保密红线

- 材料仅在本地处理，不向任何外部服务发送案件内容
- 对话、日志、产出物中一律用案件代号，不出现真实案名与当事人信息
- 交付汇报前提醒用户：机器整理、人签字——检查回链与「待核实」条目
